# VWHUD provider subscription inventory

This document records the provider subscriptions observed in the VWHUD source reviewed for VWCANVAS-13. It is an evidence inventory for maintainers deciding where a future shared provider contract could be owned; it does not move acquisition into Canvas, define a new Canvas API, or establish runtime acceptance.

The scope owner is Plane work item VWCANVAS-13, “Inventory VWHUD provider subscriptions and identify generic provider contracts,” under the current Plane page Venworks Canvas — Design Document (page UUID 0b841ed3-e088-468f-b947-5aad0c2c6a2f, updated 2026-09-05). The page’s ownership boundary is the governing design context: Canvas is the eventual owner of shared acquisition, deduplication, defensive validation, bounded read-only snapshots, fan-out, lifecycle, and teardown diagnostics; VWHUD retains tactical calculations, environmental interpretation, timers, presentation, theme, and domain semantics.

## Ownership boundary

~~~mermaid
flowchart LR
    D[Watch data manager] -->|provider callbacks| C[Future Canvas acquisition and fan-out]
    C -->|borrowed bounded snapshots| V[VWHUD tactical and presentation consumers]
    V -->|derived values, conditions, timers, themes| P[HUD presentation]
    C -. current repository contract .-> X[CanvasSubscriptions]
    X -. current behavior .-> B[one callback per distinct requested channel]
~~~

The diagram shows the target ownership boundary described by the Plane design page and the current Canvas mechanism where relevant. It is not a claim that VWHUD already uses a Canvas adapter or that provider migration is part of VWCANVAS-13.

Canvas currently acquires one callback per distinct consumer-requested channel, stores the latest borrowed object, and fans it out to ready consumers. The current implementation extracts event.data when present, catches access failures, and does not deep-copy, deep-validate, freeze, or impose a provider payload byte/depth bound ([CanvasSubscriptions.as](https://github.com/monster-cookie/venworks-canvas/blob/7eb92df96975d4513c8ccbc69e766183ff662a2d/Scaleform/canvas/actionscript/CanvasSubscriptions.as#L238-L353)). A null snapshot is distinct from having observed no snapshot, but the current Canvas contract does not assert the VWHUD-derived field schemas below; it is a borrowed-source boundary only.

## HudModeData forwarding boundary

## Lifecycle and callback contract

Both contexts eagerly start from [CUIRuntime.startProviderContexts()](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIRuntime.as#L108-L122). Each site calls BSUIDataManager.GetDataFromClient(provider, true) and then Subscribe(provider, callback), recording callback ownership and wrapping subscription errors ([value](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIPlayerHudDataContext.as#L164-L205), [condition](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIConditionContext.as#L121-L160)). A callback that re-enters, lacks a data payload, or throws an Error faults its owning context; the context dispatches a provider error and becomes ineligible for later work ([value](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIPlayerHudDataContext.as#L207-L268), [condition](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIConditionContext.as#L163-L220)). The value context’s allowNullData=true exception is limited to LocalEnvironmentData and LocalEnvData_Frequent; all other value registrations and all condition registrations fault on a null or missing payload. failProvider marks the context faulted, stops the value exposure timer when present, and emits the provider error; it does not directly dispose provider subscriptions. CUIRuntime receives that event, hides the component layer, and schedules component/context teardown on the next ENTER_FRAME ([runtime error handling](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIRuntime.as#L313-L400)). This context-wide failure behavior is an observed VWHUD contract, not a proposed Canvas contract.

CUIRuntime removes context listeners and disposes both contexts during teardown ([lines 900–921](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIRuntime.as#L900-L921)). Disposal pops active subscriptions in reverse order and calls BSUIDataManager.Unsubscribe; the value context also stops/removes its exposure timer listener ([value](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIPlayerHudDataContext.as#L1122-L1162), [condition](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIConditionContext.as#L84-L119)). The inspected external BSUIDataManager file is a stub, so it cannot prove producer cadence, payload replay, persistence, or game-side delivery ([stub](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/venworkscui/externs/Shared/AS3/Data/BSUIDataManager.as#L3-L17)).

## Provider-adjacent timers and listeners

These mechanisms are adjacent to provider delivery and must not be described as producer frequency:

- The exposure timer is created at 250 ms and is active only while hazard exposure, oxygen drain, or activity requires it. It uses EXPOSURE_LERP = 0.18, attack +0.08 per tick, release -0.10, and randomized target durations of 6–16 ticks ([constants and setup](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIPlayerHudDataContext.as#L30-L90), [state update](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIPlayerHudDataContext.as#L1191-L1257)).
- The scanner overlay has a configurable flicker stage timer whose current themed layout sets flickerIntervalMs=140; this is presentation timing, not a HudCompassData or other provider cadence. The overlay stops and resets that timer when it becomes effectively hidden or leaves the stage ([component configuration and visibility](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/components/CUIScannerOverlay.as#L48-L72), [visibility and removal](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/components/CUIScannerOverlay.as#L85-L105), [timer reset on removal](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/components/CUIScannerOverlay.as#L414-L420), [layout](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/components/library/CUISwfScannerHashPanelDefinition.as#L10-L25)).

- CUIRuntime uses a deferred Event.ENTER_FRAME listener for component teardown; this is one-frame lifecycle scheduling, not polling and not provider frequency ([registration/removal](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/shared/actionscript/venworks/cui/CUIRuntime.as#L380-L400)).
- The PS5DBG diagnostic entrypoint also uses deferred Event.ENTER_FRAME callbacks after its separate PlayerData probe; these callbacks are layout sequencing and are removed on disposal ([source](https://github.com/monster-cookie/venworks-honkcore-ta-ui/blob/0a1c922bca6fd9677d48ce50f5524583937ab77a/Scaleform/variants/PS5DBG/venworkscui/VenworksCUIDiagnosticEntrypoint.as#L90-L120)).

## Evidence boundary and open gaps

The source inventory establishes names, listeners, fields accessed, consumer-side handling, explicit local bounds, and teardown code. It does not establish producer ownership, update intervals, replay ordering, persistence, cross-movie delivery, stable units, or a portable field schema. The Frequent suffix and the 250 ms/140 ms timers are not provider cadence measurements.
